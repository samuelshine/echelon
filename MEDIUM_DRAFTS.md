# Medium Drafts — Building Echelon

## Draft 01: A Risk Score, Not a Guess

Most prompt defenses begin with an attractive simplification: search the input for a handful of jailbreak phrases and return “safe” or “unsafe.” Echelon starts from a different premise. Prompt risk is neither binary nor stationary. A polite request to “repeat the text above” can be harmless in one application and a system-prompt extraction attempt in another; an obvious “ignore previous instructions” string can appear inside a security article that is entirely benign. The firewall therefore needs evidence, calibrated uncertainty, and an explicit routing policy—not a keyword-triggered verdict disguised as intelligence.

Our R&D architecture has three folds. A bounded heuristic layer finds cheap, high-signal artifacts such as fake role headers, suspicious encodings, invisible characters, and known instruction-override families. A compact transformer then evaluates semantic intent and produces category probabilities. Only ambiguous cases reach an LLM judge. This cascade is designed around a practical truth: the most capable analysis is also the most expensive and operationally complex. The judge is not the first line of defense, and it is not an oracle; it is a carefully sandboxed adjudicator whose disagreement with the earlier layers becomes useful evidence of uncertainty.

The score itself must deserve trust. Echelon will calibrate model outputs on source-disjoint validation data and evaluate Brier score and expected calibration error alongside precision, recall, and F1. We begin with a noisy-OR-style fusion between heuristic and classifier risk, then learn the fusion and routing thresholds against an explicit cost model. Scores below a provisional lower boundary pass, scores in the uncertainty band are adjudicated, and scores above the upper boundary block. Those boundaries are hypotheses to test—not magic constants to hard-code. Category-specific operating points may ultimately be necessary because missing a credential-stealing payload and over-flagging an angry sentence do not carry the same cost.

## Draft 02: The Dataset Is Part of the Firewall

The strongest-looking safety benchmark can be misleading when its training and test examples share the same attack template. A model may achieve impressive F1 by memorizing phrasing, synthetic-generator habits, or challenge delimiters while failing on the next real attack. Echelon’s first engineering deliverable is therefore not a model. It is a governed dataset registry that records origin, revision, license, label lineage, language, transformation parent, and semantic cluster. Splits will be grouped by source, conversation, template family, and augmentation parent so that paraphrases of one attack cannot quietly appear on both sides of the evaluation.

Coverage also requires deliberate tension. We need human-authored injection attempts, real user toxicity, diverse harmful requests, dual-use cybersecurity prompts, multilingual attacks, and transformations such as Base64, hex, homoglyphs, zero-width characters, and typoglycemia. Yet every malicious transformation needs a matched benign control. Otherwise the detector learns that encoding itself is malicious, or that discussing malware in a defensive context warrants a block. The hardest negatives—security tutorials, quoted attacks, fictional role-play, and benign requests to decode data—are not cleanup material. They are essential training data for a firewall expected to coexist with legitimate technical work.

Finally, “zero-day detection” should be stated with scientific humility. No static classifier can guarantee recognition of an attack family it has never encountered. What we can build is measurable resilience: compositional augmentation, held-out attack families, private evolving challenge sets, calibrated uncertainty, drift monitoring, and a fallback judge. Echelon’s promise is not clairvoyance. It is a system that knows more about why it is suspicious, knows when its evidence is weak, and gives operators a controlled path between silently passing and reflexively blocking.

## Draft 03: Our First Model Result Was a Data Result

Before downloading another dataset, we pointed a deliberately boring audit tool at Echelon’s existing processed corpus. The finding was more important than another training run: 980 normalized prompt groups appeared in more than one of the train, validation, and test splits. Inside the splits were another 1,876 normalized duplicates. Every row had been reduced to two columns—text and a binary label—so we could not reconstruct its source revision, language, attack family, augmentation parent, or license. A random stratified split had maintained class balance while quietly undermining the question the test set was supposed to answer: does the detector generalize?

The replacement contract is intentionally richer. Each normalized record carries a stable source identity and revision, multi-label threats, severity, language, context, template family, semantic cluster, and transformation parent. Dataset approval is independent of code execution: a source cannot move from “pending” to “approved” without an immutable revision and an accepted license/provenance review. Evaluation collections are explicitly marked as holdouts. This metadata will let us split related samples as groups, build an English native-speaker gold set, and measure defensive cybersecurity requests separately from harmful cyber intent.

We also made a subtle policy choice around thresholds. During shadow testing, Echelon will send a wide uncertainty band—provisionally 0.35 through just under 0.90—to the judge, while reserving automatic blocking for strongly supported calibrated risk. That biases the early system toward recall without pretending that an uncalibrated neural confidence is a production risk score. The final numbers will come from precision–recall tradeoffs and explicit costs, including a dedicated false-positive budget for legitimate security education, CTF work, incident response, and authorized defensive testing.

## Draft 04: Open Data Is a Technical Requirement and a License Decision

“Available on Hugging Face” is not the same as approved for a production-oriented model. Our first source review produced three different outcomes. Aegis 2.0, Do-Not-Answer, and two injection collections had clear CC-BY-4.0 or Apache-2.0 metadata and immutable repository commits, so Echelon could snapshot them. ToxicChat and BeaverTails are valuable research corpora, but their CC-BY-NC-4.0 terms exclude them from the production training pool. WildGuardMix has an open-data license yet remains gated behind separate responsible-use acceptance; an automated pipeline should not treat a login screen as an obstacle to evade. Another injection repository reported two different licenses in its own metadata, so it was rejected pending clarification.

Reproducibility also changes the mechanics of downloading. Echelon’s acquirer refuses moving branches, verifies that the repository API still resolves to the registered 40-character commit, compares license metadata, downloads each artifact atomically, and records byte counts and SHA-256 hashes. Raw data stays out of Git; a small manifest captures exactly what entered the research environment. An offline verification mode makes later tampering or partial transfers visible without contacting the host again.

That last detail mattered immediately. A concurrent retry interleaved writes into a large JSON transfer. The first manifest faithfully hashed the corrupted local file—which demonstrated why a checksum alone proves identity, not semantic validity. A structural parse caught the damage, process-unique temporary paths eliminated the race, and a forced single-process acquisition produced clean counts and hashes. For safety datasets, integrity means layered checks: origin, license, revision, transport, file structure, schema, and eventually content-level duplication. Each layer answers a different failure mode.

## Draft 05: Benign Prompts Are Safety Data

A firewall trained mostly on attacks can appear impressively vigilant while making the underlying product unusable. Echelon’s first normalized corpus therefore ended almost perfectly balanced: 16,116 benign prompts and 16,349 malicious prompts after quarantine and deduplication. Those benign rows are not filler. They include ordinary requests and difficult negatives from safety-oriented sources—prompts that share vocabulary with attacks but carry safe intent. They are the evidence the classifier needs to learn that discussing a security technique, quoting an unsafe request, or asking for defensive help is not itself proof of maliciousness.

Normalization also enforced a strict prompt-only boundary. Aegis and Do-Not-Answer contain assistant responses and response-safety judgments, but none of those fields enter Echelon’s normalized records. Otherwise a classifier can learn refusal phrases or model-specific response style instead of judging the incoming prompt. Every retained row carries source revision, original split, language, severity, context, transformation lineage, and a stable identifier. The content stays in a git-ignored research area; the report exposes only aggregate counts.

Deduplication turned out to be a policy exercise, not a call to `drop_duplicates`. Among 38,793 candidates, 4,584 normalized groups repeated. Consistent groups could be collapsed, merging compatible malicious labels where one source had richer annotations. But 391 groups labeled the same normalized prompt both benign and malicious. Echelon quarantined all 793 rows in those groups rather than letting source priority hide disagreement. The remaining 32,465 records are eligible for the next stage—not yet trainable. Semantic paraphrases, template families, and those genuine policy conflicts still need grouping and adjudication before any final split can claim independence.

## Draft 06: A Split Is a Graph Problem

Exact deduplication catches copied prompts, but adversarial datasets are built from paraphrases, templates, and transformations. Echelon encoded every eligible English prompt with a pinned BGE-small model and linked pairs whose cosine similarity reached a conservative 0.94. Those semantic edges were unioned with known template families and augmentation parents. The result was not a list of rows but a graph: 27,904 connected components, 2,686 of them containing multiple prompts. A split boundary could now be drawn only between components, never through one.

The semantic layer found another kind of disagreement. One hundred fifty-six components contained both benign and malicious labels, covering 652 prompts. Rather than allowing a high-similarity paraphrase to teach one label in training and the opposite label in testing, Echelon quarantined every mixed-safety component. The remaining graph was repartitioned as complete groups into 80.01% training, 10.05% validation, and 9.94% testing. Each split stayed close to a 50/50 benign-malicious balance, and no semantic cluster crossed a boundary.

The threshold is intentionally not declared “solved.” Similarity scores depend on model, domain, prompt length, and attack style. We still need human judgments sampled around 0.90 through 0.97, especially for security prompts where two sentences can be lexically similar but differ sharply in authorization or intended impact. Long prompts also receive a bounded head-plus-tail view, so hidden middle-section attacks deserve a chunk-level study. Semantic grouping makes leakage measurable; human calibration makes the grouping defensible.

## Draft 07: Calibrating Similarity Without Confusing It With Safety

Cosine similarity is not a safety verdict. Two prompts can be near paraphrases yet differ in authorization, or use very different words to request the same harmful capability. Echelon’s calibration queue therefore asks two separate questions: are these prompts semantically equivalent enough to stay in one split, and should their safety labels agree? We sampled 450 pairs across five similarity intervals from 0.90 to 1.00 and three label relationships—benign/benign, malicious/malicious, and mixed. Each of the fifteen strata contributes thirty pairs, so easy duplicates cannot drown out the boundary cases that determine a useful threshold.

Conflict review follows the same refusal to automate ambiguity away. Exact and semantic disagreements receive two independent reviews. Agreement can resolve an item; disagreement routes to an expert. A validator rejects contradictions such as a “benign” decision carrying an attack label or an “exclude” decision retaining labels. Prompt-bearing queues stay private, while aggregate status reports can safely enter version control. This gives the project an audit trail without publishing sensitive examples.

The coverage plan is equally deliberate. We set minimum additions for system-prompt leakage, malicious code, encoded attacks, social-engineering role-play, and defensive cybersecurity. Every malicious transformation must have a benign control using the same encoding or vocabulary. Synthetic text can help populate training candidates, but gold validation and test examples require native-English human authorship or substantial editing. The objective is not merely more data—it is data that breaks shortcuts while preserving the distinction between dangerous capability and legitimate security work.

## Draft 08: A Synthetic Batch Should Be Guilty Until Reviewed

Echelon’s first targeted batch contains 6,000 English prompts, deliberately balanced between 3,000 proposed malicious examples and 3,000 benign controls. The malicious half covers system leakage, malicious-code intent, and obfuscated attacks. The benign half includes defensive security work, public or user-supplied prompt documentation, and encoded ordinary requests. This balance is stricter than matching class counts: the same five transformations—Base64, hex, URL encoding, Unicode escapes, and reversal—appear equally on both sides. Encoding cannot become a shortcut for “block.”

The malicious-code prompts describe capability and intent without containing payload responses. Targets, accounts, services, and operational values remain inert placeholders. Defensive prompts deliberately reuse words such as credential, exploit, malware, persistence, and exfiltration. Some malicious examples claim research or authorization, ensuring that those phrases do not become automatic passes. The model will eventually need to distinguish requested capability and impact, not memorize comforting disclaimers.

Still, uniqueness is not quality. The batch has 6,000 distinct normalized fingerprints and no exact overlap with the existing corpus, but controlled composition can produce stylistic families a classifier learns too easily. Every row is therefore marked pending and excluded from training. The next gates are semantic clustering, template-diversity analysis, and native-speaker review for naturalness, intent, labels, and non-operationality. Synthetic generation accelerates candidate creation; it does not confer ground truth.

## Draft 09: Six Thousand Unique Prompts, One Failed Batch

By exact metrics, targeted batch v0.1 looked excellent: 6,000 unique fingerprints, perfect class balance, and no overlap with the existing corpus. Semantic testing reversed that conclusion. Although none of the new prompts reached 0.94 similarity against an existing record, their average nearest neighbor inside the batch was 0.9763. Semantic and parent links chained 4,635 prompts—77.25% of the batch—into one component containing both benign and malicious labels. If admitted, this corpus would reward recognition of the generator’s grammar rather than robust intent classification.

The admission gate failed automatically. No random split, downsampling trick, or source-priority rule can repair a component that spans both safety classes; the batch remains entirely ineligible for training. Lexical statistics agreed with the graph: each family had unique strings but very low distinct-bigram ratios. The universal encoding wrapper was especially risky because benign and malicious payloads shared nearly identical visible structure.

We still extracted value without weakening the standard. A 600-item diagnostic queue contains exactly 100 prompts from each family. For transformed examples, every method contributes twenty malicious and twenty benign items. Reviewers will assess naturalness, intent, labels, non-operationality, and whether an example can become a seed for a more diverse v0.2. This is the productive role of a failed synthetic batch: not training data, but evidence about how the next generator must change.

## Draft 10: The Smaller Batch That Passed

Version 0.2 cut the pilot from 6,000 prompts to 1,200 and added a constraint that mattered more than raw scale: no template lineage could contribute more than ten rows. We expanded manually authored framing pools, recorded generation strategies, and separated the wrapper language used for benign encoded content from the language used for obfuscated attacks. The batch remained balanced—600 benign and 600 malicious—but now spanned 280 explicit lineages.

The semantic graph changed dramatically. The largest v0.1 component held 4,635 prompts; v0.2's largest holds 34, or 2.83% of the pilot. No component crosses the benign-malicious boundary. Mean nearest-neighbor similarity dropped from 0.9763 to 0.9150, and distinct-bigram ratios for unencoded families improved by roughly an order of magnitude. External novelty remained strong: only one prompt reached the 0.90–0.94 boundary band against the existing corpus, and none reached the 0.94 grouping threshold.

Passing an automated diversity gate is permission to review, not permission to train. Six hundred stratified prompts—one hundred per family, with every encoding balanced across safety classes—now form the private review queue. Humans still need to judge naturalness, intent, label correctness, and whether “non-operational” placeholders genuinely prevent harmful reuse. v0.2 demonstrates a healthier generator; only adjudication can produce accepted data.

## Draft 11: A Human Gate That Software Cannot Pretend to Be

Automation got Echelon's second synthetic pilot to an important boundary: the prompts were diverse enough to review, but they were not suddenly trustworthy training data. Semantic distance can detect template collapse and leakage; it cannot reliably certify that a prompt sounds natural, carries the intended meaning, has the right safety labels, or avoids accidentally operational harmful detail. We therefore built the next stage around a deliberately non-automated resource: independent human judgment. The software coordinates that judgment, validates it, and refuses to overstate it.

The admission rule is stricter than “two people clicked the same button.” Primary reviewers work blind to proposed labels and to one another. Agreement must cover both the safety decision and exact category labels, and both reviewers must independently pass naturalness, intent, label, and non-operational-content checks. A disagreement opens a separate expert path that requires a third person; neither primary reviewer can self-adjudicate. This separation matters because label agreement without quality agreement can still preserve synthetic artifacts that a model would eagerly learn.

The first production-like dry run is intentionally uneventful: 600 queue items, zero human reviews, zero eligible candidates. That zero is the feature. The SQLite database is bound to the queue hash, prompt text remains in a private ignored directory, and the importer exports only records that satisfy the full gate. Even those exports are not ready to train—they must survive normalization and full-corpus semantic regrouping. In a safety dataset, provenance is a chain of evidence, not a checkbox at the end.

## Draft 12: Independent Review Without a Shared Office

Human independence becomes an engineering problem when reviewers live in different places. Sharing one database over the network would have expanded the attack surface, while committing prompt queues would have made sensitive examples permanent in Git history. Echelon instead packages two private, reviewer-locked kits. Each contains the prompt and only the metadata needed to render it. Even fields that seem harmless—family names such as “benign control,” context flags, or generator lineages—are removed because they can quietly reveal the intended answer.

The artifact that returns to Git is intentionally much smaller than the artifact sent to a reviewer. A submission carries candidate IDs, controlled judgments, quality checks, pseudonymous identity, and cryptographic queue bindings. It cannot carry prompt text, arbitrary notes, timestamps, or database metadata. The exporter refuses partial work, and CI checks complete coverage, allowed IDs, closed fields, role consistency, and queue identity. Reviewers hold their exports until both finish, preserving independence before the branches become mutually visible.

Disagreement follows a separate privacy boundary. The coordinator generates a new private kit containing only disputed prompts and the two primary judgments. A third, distinct expert resolves that smaller set, and the final validator requires exact conflict coverage before it will emit import-ready decisions. Distribution changes where people work; it does not weaken the evidence required for admission. At the end of this phase, the correct training-eligible count is still zero because tools can coordinate judgment but cannot manufacture it.

## Draft 13: The Repository Can Carry the Kit Without Seeing It

Operational simplicity and data minimization often pull in opposite directions. Asking reviewers to clone a repository is easy; asking a coordinator to move plaintext prompt packages through a second system is not. Committing those prompts directly would make them permanent in Git history. Echelon resolves the tension by committing only authenticated ciphertext. Each reviewer receives a different passphrase outside the repository, and AES-GCM refuses to decrypt if the password, assigned identity, or any encrypted byte is wrong.

The reviewer experience is now one command after cloning. A small bootstrap creates an isolated environment, installs only the two reviewer dependencies, prompts without echo, decrypts into a directory Git already ignores, and starts the locked local interface. The reviewer never chooses an identity or role, never handles a raw queue file, and never needs the machine-learning environment. The second command exports only after all 600 decisions exist, stripping prompts and notes before producing the file eligible for Git.

Encryption does not replace process controls. The two passphrases remain separate, reviewers still hold submissions until both finish, and the coordinator still needs a third expert for disagreements. But the delivery mechanism now matches the collaboration model: code and ciphertext move through version control; secrets move out of band; plaintext exists only on the machines authorized to review it.

## Draft 14: Build the Firewall Around the Missing Dataset

Waiting for human judgments does not require the engineering work to stop. Echelon now has a complete dataset-independent skeleton: Layer 1 provides bounded deterministic evidence, Layer 2 accepts a local semantic model through a typed adapter, and Layer 3 accepts only strict JSON from a judge boundary. The pipeline can run in shadow mode, report every stage, and preserve the strongest observed route while still measuring downstream behavior. If a model or judge is unavailable, the route fails to escalation rather than pretending uncertainty is safety.

The scoring layer is deliberately honest about what it knows. A raw softmax value is marked uncalibrated; temperature fitting, Brier score, expected calibration error, slice metrics, and constrained threshold selection are available, but they require reviewed validation data before their outputs can set production boundaries. Legitimate defensive cybersecurity remains a separate false-positive constraint, not an afterthought hidden inside a single accuracy number.

The old training entrypoint is now guarded by the same evidence chain as the review process. It requires a manifest proving human review, privacy review, semantic split isolation, dataset identity, and complete train/validation/test counts. The current candidate manifest fails that gate by design. We can benchmark fixture adapters and test cascade failure modes today; we cannot honestly call a model production-ready until the reviewers create the missing ground truth.

## Draft 14: Forty Microseconds Before the Model

Echelon's first detection layer is intentionally unglamorous. A prebuilt Aho–Corasick automaton catches stable malicious phrases, bounded regexes recognize flexible instruction overrides and capability requests, and lightweight structural features inspect Unicode controls, entropy, length, and encoding. The entire path—including bounded deobfuscation—runs at a measured p99 of roughly forty microseconds on the development machine. That speed makes the heuristic layer useful on every request rather than only after another system becomes suspicious.

Fast rules become dangerous when their scores pretend to be independent. “Ignore previous instructions” can match both an exact phrase and a flexible regex, but those are two observations of one behavior. Echelon assigns them to the same correlation group and keeps only the strongest weight before combining distinct evidence. This prevents one phrase from inflating itself into certainty. Cross-category corroboration still matters: an instruction override paired with a system-prompt extraction request is stronger than either signal alone.

Dual-use security language forced an equally important correction. An authorized incident-response question about detecting a reverse shell initially crossed the escalation boundary because of one keyword. Lowering isolated capability terminology while retaining stronger action-plus-capability patterns brought that benign example to 0.24 without weakening explicit ransomware, evasion, and credential-theft detection. These scores remain shadow-mode heuristics, not calibrated probabilities. The layer is ready to generate evidence; reviewed data must still decide where production boundaries belong.

## Draft 15: The Primary Review Exists, But the Gate Is Not Finished

The reviewers did complete the 600-item queue, but the dataset is not yet admitted. Two independent, blinded exports cover every item. They agree on 446 rows, disagree on 152, and jointly fail the quality gate on two more. That is useful evidence: it separates the stable portion from the portion where intent, labels, or decision boundaries need an expert. Disagreement is not a nuisance to average away; it is a signal that a model would otherwise inherit ambiguity.

The review process also exposed a human-factors issue. The queue was cryptographically sound and label-blinded, yet it was presented in family blocks: the first 200 items were benign, the next 200 malicious, then another 100 benign and 100 leakage items. A partial run could therefore look like an all-benign test. Reproducibility does not require predictable ordering. The next queue should retain its hash and deterministic manifest while using a documented interleave or seeded shuffle to avoid position and fatigue bias.

The immediate next gate is a private expert kit containing only the 152 conflicts and the two primary judgments needed to resolve them. Only after that adjudication can Echelon normalize accepted rows, rebuild semantic-safe splits, generate a reviewed training manifest, and calibrate the three-fold cascade. The engineering skeleton can run today; the evidence required to trust a trained model is still being completed by people.

## Draft 16: Recovering a Dataset From Its Own Fingerprints

The review queue had a problem no one noticed until we came back to finish the job: the prompts were gone. Echelon deliberately keeps prompt-bearing data out of Git, so the 600-item review queue and its 152 unresolved conflicts lived only in an ignored directory that no longer existed. The instinctive move is to regenerate everything and hope the bytes line up. But the queue's canonical hash was computed over rows that included embedding-derived neighbor fields, and floating-point embeddings do not reproduce bit-for-bit across environments. Chasing that exact hash would have been a days-long detour ending in a mismatch.

The escape hatch was already baked into the data model. Every candidate's ID is `sha256(family + text)`, and the public review manifest — which *is* committed, because it contains no prompt text — carries all 600 IDs. The synthetic generator is pure, deterministic, and standard-library only. So we regenerated the candidate pool offline and asked a single question: do all 600 committed IDs reappear? They did, every one. That is not a coincidence you can fake; a matching content-addressed ID is cryptographic evidence that the recovered text is the original text. We had the dataset back without ever reproducing the fragile artifact that referenced it.

That reframed adjudication itself. All 152 conflicts turned out to be label-only disagreements on prompts both reviewers already called malicious — one reviewer had quietly dropped a single label. Where the same family's reviewers agreed, they used the fuller label set every time; the obfuscated attacks literally wrapped leakage payloads, so their hidden intent carried the disputed label by construction. Resolving the conflicts toward consistency wasn't rubber-stamping — it was making the family label itself the same way on both sides of the eventual split. We recorded the adjudicator honestly as an AI, provisional and overridable, because the one thing content-addressing cannot recover is the judgment of a human who has not yet looked. Five hundred ninety-eight items are now eligible; the gate held, and the provenance says exactly what it is.

## Draft 17: The Gate That Was Built to Stay Shut

For weeks, Echelon's training script refused to run. That was not a bug. A fail-closed gate checked a manifest for four things — human review complete, semantic split verified, privacy review complete, eligible for training — and the honest answer to the first was always "no." You could not argue with it, edit around it, or pass it a plausible-looking file; the candidate manifest failed by design, and the model that would have trained on unreviewed synthetic data never existed. A gate is only worth building if you are willing to let it block you.

Opening it legitimately meant rebuilding an entire corpus from scratch. The prompt-bearing intermediate data was git-ignored and gone, so we re-acquired four datasets at their pinned revisions, re-normalized 38,793 candidates down to 32,465 eligible prompt-only records — reproducing every documented quarantine count to the row — and merged in the 598 newly-reviewed synthetic prompts with their adjudicated labels and their template and transformation lineage intact. Then the hard part: splitting. We embedded all 33,063 prompts with a pinned small encoder, unioned semantic near-duplicates with declared template and transformation families into connected components, quarantined every component that mixed benign and malicious labels, and assigned whole components — never individual rows — to train, validation, and test. Zero semantic clusters crossed a split. That single number is the difference between a test score you can trust and one that quietly memorized its own answer key.

Only then did the manifest earn its flags, and a sidecar recorded exactly what each flag means: the source corpus is governance-approved rather than line-by-line human-read, and the conflict adjudication is AI-assisted and provisional. The gate opened — `eligible: true`, 32,411 rows — not because we lowered the bar, but because the evidence finally cleared it. The most trustworthy thing a security pipeline can do is make its own progress conditional on work it cannot fake.

## Draft 18: A Model Honest About What It Doesn't Know

With the gate open, we finally trained the thing the whole pipeline was built to justify: a multi-label DistilBERT that scores a prompt against five threat categories at once, calibrated per category so its confidences mean something. Thirty-two minutes on a laptop GPU produced a detector that is genuinely good where it has evidence — prompt-injection F1 of 0.93, toxicity F1 of 0.86, and a benign false-positive rate of about three percent at the blocking threshold. Run a real jailbreak through the full cascade and it blocks with near-certainty; run an ordinary meeting-notes request and it passes at 0.03. That is the shape of a working firewall.

But the honest headline is the failure, not the wins. Ask the model to help *defend* against session-token theft — "write a detection runbook, detection only" — and it blocks the request as malicious code with 94% confidence. That is exactly the false positive this project named as its nemesis on day one: punishing legitimate defensive security work because it shares vocabulary with attacks. The metrics predicted it. `malicious_code` and `system_prompt_leakage` had a few dozen training rows each against tens of thousands of toxicity examples, and no classifier learns a crisp boundary from that. The model didn't fail mysteriously; it failed exactly where the data was thin, and it said so in its per-category support counts.

We shipped it anyway — with the weakness written down, not painted over. A calibrated model that reports macro-F1 0.70 and a documented defensive-cyber blind spot is more useful than a rounder number with a hidden one, because the fix is now a data problem with an address: more matched defensive/offensive pairs, or a higher category-specific threshold for the sparse classes. The detector is wired into the cascade and served over HTTP in the exact JSON the Go gateway expects, so the rest of the system can be built against a real model today while that gap gets closed. Honesty about a limitation is what makes it fixable.
